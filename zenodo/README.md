The code that produced these are hosted at https://github.com/ricsatjr/landscape-evolution-ml, licensed under GPL-3.0. It is refactored from the original code stored in a private github repository. 

Unless otherwise stated, commit hashes refer to commits at the repository level, not at the file level.  

This deposit has the following layout. Extract it with the directory structure intact: files under data/models are named identically across n01 and n10, and are distinguished only by their paths.

    pipeline/          code that produced everything below
    data/
      landscapes/      LEM parameter sets, elevation-grid samples, screening
      rasnet/          processed rasters and drainage networks (stage 1 of
                       feature extraction), ss-n10 and ss-n1
      features/        morphometric features, n10 and n01
      models/          trained ML models, n10 and n01

What is inside each file — DataFrame columns, dictionary keys, algorithm labels — is described under File contents at the end.

# Environment

The pickle files here were written under the environment pinned in environment.yml in the code repository: python 3.12.2, numpy 2.0.1, scipy 1.15.1, pandas 2.2.3, scikit-learn 1.6.1, landlab 2.9.2, networkx 3.4.2. Recreate it before loading them:

    conda env create -f environment.yml
    conda activate leml

Two groups of pickles are version-locked and will not load otherwise:

- the model pickles under data/models embed fitted scikit-learn estimators and
  fail on a different scikit-learn release; under 1.9.1, for example, with
  "ModuleNotFoundError: No module named '_loss'"
- the rasnet pickles under data/rasnet hold a landlab RasterModelGrid and a
  networkx DiGraph, so both packages must be importable. They also reference
  numpy._core, which exists only in numpy 2.0 and later.

The DataFrame pickles (params-*.pkl, features-all-*.pkl) did load under newer numpy and pandas in testing, but were written and verified only under the pinned versions. The .csv, .npy and .npz files carry no such constraint.

# data/rasnet

Intermediate output of stage 1 of 02_extract_features.py: a Landlab raster grid with measurement noise applied, its drainage network, and watershed outlets, saved before the morphometric features are computed in stage 2. Stage 1 runs in hours per landscape, so these are included to let feature computation be repeated without rerunning flow routing.

Filenames follow the convention the code reads and writes, rasnet-n{elev_err}-{job-id}-{landscape-idx}-{ts-index}.pkl, so the noise level appears here as **n1** and **n10**, not the n01 and n10 used by the features and models folders. Do not rename them: 02_extract_features.py constructs these names directly and silently skips any file it cannot find.

## /ss-n10
**rasnet-n10-<job-id>-<landscape-idx>-99.pkl**
- sample of landscapes processed with added elevation error [-10,10] meters
- full data set to be provided upon request

## /ss-n1
**rasnet-n1-<job-id>-<landscape-idx>-99.pkl**
- sample of landscapes processed with added elevation error [-1,1] meter
- the same landscapes as /ss-n10, so each can be compared against its pair
- full data set to be provided upon request

Each pickle is a flat list [le_params, mg, mask, chNet, wsOutlets, wsOutletsDA], where mg is a landlab RasterModelGrid and chNet a networkx DiGraph. Both packages must be importable to unpickle and because mg precedes chNet the network cannot be read without instantiating the grid.

The landscapes here are among the elevts samples in data/landscapes, and the
measurement noise is seeded from the filename as int(f"{job_id}{landscape_idx}{ts_index}") + 1, so every file here can be regenerated exactly from its elevts grid by rerunning stage 1 — see the Usage section of 02_extract_features.py.

# File contents

**params-<job-id>.pkl** — pandas DataFrame, 10 rows (one landscape each) x 18
columns. The join keys are named differently here than elsewhere: tmux-sess is
the job ID (job_id elsewhere) and df-ind the landscape index (landscape_idx
elsewhere). Columns: u, kh, ks, dx, ly, T, hc, lc, minlc, maxlc, lc_in_range,
reliefOK, tmux-sess, df-ind, nX, nY, ts_mean_elevs, ts_max_elevs. The last two
are 100-step elevation time series; ts_max_elevs is a maximum-elevation series
alongside the mean.

**features-all-<hash>.pkl** — pandas DataFrame, 1500 x 47: nine identifier and
label columns (u, kh, ks, elev_err, job_id, landscape_idx, ts_index, u_ks,
kh_ks) and 38 morphometric features. elev_err is the noise amplitude in metres
(1.0 or 10.0), not a per-cell value.

**nested-cv-results-*.pkl** — dict keyed by algorithm, plus _meta:

    lin  LinearRegression            lso  MultiTaskLasso
    knn  KNeighborsRegressor         svm  SVR (MultiOutputRegressor)
    dtr  DecisionTreeRegressor       rfo  RandomForestRegressor
    gbs  GradientBoostingRegressor (MultiOutputRegressor)
    mlp  MLPRegressor

Every model is a Pipeline with StandardScaler. Each algorithm entry holds
per-outer-fold test_r2, test_mse, test_rmse and test_mae, best_params,
per_target_* and mean_test_* summaries, and final_model, whose regressor key is
the fitted Pipeline.

_meta records the run: feature_names, label_names, job_ids, retained_csv,
id_keys, train_ids, test_ids, n_outer_splits (10), n_inner_splits (5), n_iter
(20), random_state (42), git_hash. Full-feature files add test_fraction (0.2)
and features_hash; reduced files add reduced_feature_names, run_tag,
cluster_threshold, cluster_selection, domain_features, allow_cluster_collisions
and full_models_pkl. train_ids and test_ids give the split by landscape
identity (1153 / 288), so it can be reapplied exactly. Reduced files produced by
the current code also record source_git_hash and cluster_info, the latter
holding the cluster membership, Ward linkage, dendrogram leaf order and
distance matrix.
